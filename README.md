# 天途 CRM · 移动工作台 V1.1

参考探迹移动端界面和 [天途管理端](https://xingyuzhang65-cloud.github.io/tiantu-crm-admin/web/) 的跨境物流业务结构实现。

## V1.1 手机界面

五个主页面采用手机 APP 布局，取消桌面侧栏和首页营销标题。统一顶部搜索、固定五栏导航、客户全宽列表、四列应用宫格与个人菜单；正文 15–16px，输入框 16px，适配顶部和底部安全区。

新增与编辑采用全屏表单和固定底部操作栏。详情内进入编辑、跟进等操作后，返回或保存会回到上一层详情。支持应用搜索、联系人/通话记录切换，以及手机桌面图标和独立窗口启动配置。

## 本地运行

Node.js 22.13+。安装依赖后运行 `npm run dev -- --port 5186`，打开终端显示的本地地址。
本地测试身份通过 `/signin-with-chatgpt?return_to=/` 登录，仅在 loopback 开发预览中生效，生产身份由 Sites 提供。

初次初始化本地 D1：先 `npm run build`，再执行：

```powershell
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_warm_fallen_one.sql
```

## 已实现

- 客户档案、等级、阶段、公海认领与退回、查重、搜索和筛选。
- 跟进内容与沟通方式、阶段同步、超过五天未跟进提醒。
- 关联客户的待办、到期/逾期提醒、完成与恢复。
- 询价、线路、品类、运输方式、重量体积、报价金额、币种、有效期与状态维护。
- 运单创建、运输节点、异常与解除记录。
- 单独的资料信息流：发票、箱单、提单准备状态与 HTTPS 外部文件链接。
- 应收和授信人民币手工台账、数据统计、JSON 导出。
- 手机系统拨号、个人资料、帮助、可选演示客户和一键清除演示数据。
- 云端 D1 保存，接口登录鉴权、用户数据归属校验、输入校验、跨来源写入拦截。

## 需求反讲与权限范围

主要流程：录入/认领客户 → 记录沟通 → 安排回访 → 询价与核价 → 维护报价 → 建立运单 → 分别维护资料和货物运输轨迹 → 跟踪异常解除。

页面支持公开访问，个人业务数据按登录账号隔离。登录后可操作本人所有字段和业务按钮。销售、运营、财务等多人角色尚未开放；后续销售只访问分配客户及业务，授信额度和财务字段限定财务/管理员，并由服务端执行字段、菜单、按钮权限。当前没有仅靠前端切换角色的模拟权限。

## 管理端集成边界

参考管理端的 `web/static/admin-pages.js` 使用浏览器 localStorage 与 fetch 模拟接口，不是可共享的线上后端。本版数据单独云端保存，尚未与管理端实时同步。后续需统一真实 API、业务 ID、成员、数据权限与迁移方案。

外部企业数据库、自动外呼、微信自动化、承运商轨迹接口、手机推送、文件上传和外部 AI 尚未接入。报价、授信、运踪均明确标记为人工业务台账；业务助手使用当前数据规则汇总。

## 验证

- `npx tsc --noEmit --incremental false`
- `npm run build`
- 启动本地服务后 `node scripts/verify-crm.mjs`，验证完整业务链、鉴权、归属、查重、异常流与关联删除。

浏览器 UI 验证受本次环境限制，无法可靠识别浏览器 URL，因此停止浏览器自动化；需人工复核 360/390/430px 设备宽度。

## 部署

`.openai/hosting.json` 保存 Sites 项目标识，D1 绑定为 `DB`。生产发布通过 Sites 版本/部署工作流执行，迁移会随发布应用。不要将本地运行状态、数据库、环境变量或凭证提交到仓库。
